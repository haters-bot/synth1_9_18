# 振荡器实体数与时分复用容量验证

## 目标

本阶段验证两个参数独立的振荡器同时工作时，是否能支持：

- 8 个独立复音；
- 每个复音 `Unison=8`；
- 每个振荡器需要 `8 × 8 = 64` 个任务槽位；
- 一个振荡器使用 Acid 三维波表，另一个振荡器使用锯齿波，确认两路参数和波表访问彼此独立。

这里的“三维波表”是当前工程中的 16 帧 × 256 点 Acid 波表。`wt_position[6:3]` 选择相邻帧，`wt_position[2:0]` 做帧间线性插值；每个实体引擎各自例化一个双口同步 ROM 读取器。

## 调度预算

系统时钟为 50 MHz，内部采样率为 768 kHz。相邻内部采样请求间隔约为 65 或 66 个系统时钟。

一个实体引擎的流水线填满后每拍提交一个槽位，因此单引擎需要约：

```text
完成时间 ≈ SLOTS_PER_ENGINE + 流水线尾拍
```

测试使用 65 拍的紧预算。这样可以把“能完成”与“有足够时序余量”区分开：1×64 虽然能在 65 拍下完成，但在 64 拍压力下会置位 `schedule_overrun`，说明余量只有约 1 拍。

## RTL 仿真结果

测试平台：

- `sim/tb_dual_osc_capacity.v`：两个独立 Bank，64 个任务全部启用；
- `sim/tb_scheduler_unison8_capacity.v`：2×32 调度器，发送 8 个音符，每个音符 Unison=8；
- `sim/run_capacity_sweep.do`：比较 1×64、2×32、4×16、8×8。

### 65 拍预算

| 实体引擎 × 每实体槽位 | 总槽位 | 两路 Bank 输出 | 调度溢出 |
|---:|---:|---|---|
| 1 × 64 | 64 | 12/12 个样本有效 | 无，但余量很小 |
| 2 × 32 | 64 | 12/12 个样本有效 | 无 |
| 4 × 16 | 64 | 12/12 个样本有效 | 无 |
| 8 × 8 | 64 | 12/12 个样本有效 | 无 |

### 64 拍压力

`2×32`、`4×16` 和 `8×8` 仍然通过；`1×64` 产生 `schedule_overrun`。这说明 1×64 不适合作为保守的上板配置。

### 调度器验证

`tb_scheduler_unison8_capacity.v` 已通过：

```text
PASS: 2x32 scheduler allocates 8 notes at Unison=8 (64 tasks)
```

此前 `active_task_count` 只有 6 位，无法表示 64。现在已扩展为 7 位，并把 32～64 的倒数增益表补齐；64 个任务对应 `1/64 = 1024/65536`。

## 当前建议

推荐后续实际工程采用：

```verilog
OSC_ENGINE_COUNT = 2
SLOTS_PER_ENGINE = 32
```

理由是：

1. 满足双振荡器、8 复音、Unison=8 的 64 任务要求；
2. 每个实体只需处理 32 个槽位，远离 65 拍边界；
3. 相比 4×16、8×8，实体 ROM、包络状态寄存器和波表读取器数量更少；
4. 相比 1×64，布线拥塞和关键路径风险更低。

这只是 RTL 和综合前的容量结论。最终资源占用、最高频率和布线时间仍需用高云综合布线报告确认，尤其要检查 Acid ROM 是否按预期映射到 BSRAM。
