# 滑带异常：ADS1256协议独立审查

日期：2026-11-02。生产源码 HEAD：62535f3；用户确认当前烧录版本：92476d0。

## 结论及证据边界

当前最优先、已有直接证据的问题是 ADS1256 的 DIN 输出不满足芯片的采样建立/保持时间。
92476d0 在 SCLK 下降沿同时更新 DIN，62535f3 改为延后一个系统时钟，但50 MHz下一拍只有20 ns，仍小于手册要求的50 ns。
因此上一轮“仿真通过”不能作为SPI已修好的证据。

这足以使 ADC 命令、MUX、采样率等写入不可靠，从而使读出的数据不能作为有效滑带电压。
但仅有串口原始码和RTL仿真，不能证明板上的每次跳变均由此造成，也不能排除SYNC电平、共地、模拟输入等问题。
需要正确协议下的寄存器读回及固定电压实测来完成根因闭环。

## 1. 原始日志

输入：用户提供的 cb40b380-3b87-4ed2-b3f4-7140f8e6ebd1 附件。
980个24位样本，按已约定的VREF=2.5 V、PGA=1换算：

- 454个样本为负数；13个超过3.3 V；范围约−4.9276～+4.9886 V。
- `936C97`对应约−4.2412 V，`7EB980`对应约+4.9502 V。
- 先前实测松手约0.08 V，理想码约`020C4A`；按下有效端点约0.807～2.378 V。
- 578个样本最低字节与最高字节相同。这是值得检查串行读取及配置的线索，不足以单独证明某种字节移位。

串口发送的是前端原始码的快照。这些异常在音高映射、ADSR、振荡器之前已经出现。
真实大幅跳变会反复跨越Gate阈值，并导致大范围音高变化；增加平滑不能替代修复采集协议。

## 2. 确定的时序缺陷

TI ADS1256数据手册第6页Figure 1及Timing Characteristics规定：

- DIN在SCLK下降沿前建立时间t4至少50 ns。
- DIN在SCLK下降沿后保持时间t5至少50 ns。
- ADC从SCLK上升沿更新DOUT，主机可在下降沿采样。

| 版本 | DIN变化时刻 | 结论 |
|---|---|---|
| 92476d0（用户当前板上版本） | 与SCLK下降沿同一系统拍 | 未提供建立/保持裕量，板上结果受输出延迟差影响 |
| 62535f3（当前源码） | 下降沿后一拍，即20 ns | 仍小于50 ns |
| 审查用候选 | 在SCLK上升沿更新当前位 | 1 MHz下相邻下降沿相距约500 ns，能提供更大裕量 |

候选仍需在真实FPGA引脚上考虑IO延迟和布线偏差，RTL周期差不等于完成板级时序签核。

## 3. 初始化及状态可见性不足

生产代码写入`STATUS=04`使ACAL=1，同时把DRATE从复位F0改为E0；这会触发自动校准。
引脚解码测得随后约14.12 us又发出SELFCAL，而数据手册15 kSPS/PGA1对应的自校准时间约696 us。
当前实现没有等待自动校准结束，混用了自动及手动校准两种流程。

另外，硬件RESET释放后即发送软件RESET，没有等待硬件复位后的自动校准完成。
这种冗余复位时序应规范化；不能仅凭模型中的“校准期间发命令”提示推断它已造成实际校准错误。

FPGA没有RREG读回校验。`I1`仅表示控制器走过初始化状态；`VF`只表示四路都提交过数据。
两者均不能证明芯片ID、STATUS、MUX、PGA或DRATE正确。

STM32参考代码的差异：

- 默认STATUS=00，关闭ACAL和输入缓冲；随后执行一次手动SELFCAL并等待DRDY。
- 默认1000 SPS，FPGA当前15000 SPS。速率差异影响建立时间和噪声，但不能单独解释几伏的负值跳变。
- 读取STATUS、MUX、ADCON、DRATE、IO，发现不匹配时记录错误信息。
- STM32的`ads1256_begin()`在寄存器不匹配后仍返回true，移植时应强化为明确校验失败，不能照抄为成功。

## 4. 先前测试为何漏检

`sim/tb_ads1256_scanner.v`：

- 使用20 MHz系统时钟，非板上50 MHz。
- 新增DIN检查只等待1 ns，没有按t5要求检查完整50 ns窗口。
- 使用2 MHz SCLK；在7.68 MHz ADC主时钟假设下高于fCLKIN/4。
- RDATA等待被缩短为2个系统周期，且未用真实芯片时序模型约束。
- 按`dut.sequence_kind / sequence_index / spi_bit_index`直接返回固定测试字，绕过了真实ADC的命令接收、配置寄存器和独立移位过程。
- DRDY由测试平台观察控制器状态后人工提供；无法证明真实ADC会因正确命令产生对应DRDY。

原测试能检查部分内部状态推进，不能证明端到端ADS1256通信有效。

## 5. 本次可复现审查

新增：

- `sim/tb_ads1256_protocol_audit.v`：实际50 MHz/1 MHz，仅通过CS/SCLK/DIN/DOUT/RESET/DRDY交互，不读取dut内部状态；独立解码命令、寄存器写入和24位数据。
- `sim/run_ads1256_protocol_audit.do`：运行审查。

这个模型是依据手册写的协议检查器，不是TI器件模型；为了收集后续错误，记录违规后仍继续执行命令。
模拟电源、输入阻抗、真实校准结果、走线延迟等不在模型范围内。

实测仿真结果：

| 被测代码 | 观察结果 |
|---|---|
| 92476d0 | 89次采样沿附近DIN时序违规；模型把FE解码为FC；8个样本均不匹配 |
| 62535f3 | 89次t5=20 ns违规；2处校准等待风险；理想接收条件下8个样本匹配 |
| 临时候选（上升沿更新DIN、关闭ACAL、硬件RESET后延时再配置） | 同样8个样本下，建立/保持、校准等待、数据、RDATA间隔及SYNC间隔检查均为0项异常 |

92476d0的具体错码由仿真事件及相对延迟决定，不能当作真实板上已经抓到的FE→FC波形。
可以确认的是同时变化没有协议规定的裕量；62535f3的20 ns不足则可直接由周期计算确定。
临时候选通过仅用于验证整改方向，尚未作为生产修复合入。

运行：

```powershell
vsim -c -do "do sim/run_ads1256_protocol_audit.do; quit -f"
```

检查终端的`AUDIT SUMMARY`计数；仿真进程退出码0不表示被测协议合格。

## 6. 建议整改与验收顺序

1. DIN改在SCLK上升沿更新，保留足够下降沿建立/保持裕量；继续在下降沿接收DOUT。
2. 初始化统一使用ACAL=0及一次手动校准；复位/校准完成由DRDY确认，加入有界超时及失败状态。
3. 增加RREG，校验芯片ID和STATUS、MUX、ADCON、DRATE等配置；通道切换也能读回MUX进行诊断。校验失败不得标记初始化成功并把数据送去发声。
4. 用50 MHz和独立ADC协议模型验证；保留读数非零、通道区分、背压及错误配置的测试。
5. 板上先测已知固定电压和地，确认原始码及寄存器，再接滑带验证位置映射。

无需通过修改振荡器规模、ADSR或加重滤波来解决这项协议缺陷。
MIDI滑音隔离和在途样本保护属于另外两项合理的声音路径修正，无法修复ADC原始码。

## 7. SYNC硬件条件

用户确认未找到SYNC引脚。此前提供的模块照片中，右侧P3双排针左列最下端丝印为SYNC，位于RST下方，与DOUT相对。
SYNC/PDWN为低会停止通信，持续低电平会进入掉电；它应保持模块数字电源DVDD的高电平。
模块是否已通过板载电阻上拉，照片不足以确认；不应直接认定“没接线就是悬空”，需测量该脚对GND电压或查看模块原理图。
不要把模块5V供电等同于其数字控制高电平；卖家资料说明数字接口为3.3 V。
