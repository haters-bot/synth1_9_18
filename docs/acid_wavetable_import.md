# Acid波表导入与WT Position实现报告

## 1. 输入文件分析

本次输入为`Acid.wav`。文件属性如下：

| 项目 | 数值 |
|---|---:|
| 声道 | 单声道 |
| 编码 | 16位PCM |
| WAV采样率字段 | 44.1 kHz |
| 总采样数 | 81920 |
| 源帧长度 | 2048点 |
| 源帧数量 | 40帧 |

本次转换所用输入文件SHA-256为
`674EC840A38BF9170FBDA36609E7D4ADE1BE7F093F4115D0253B80A2318DECA2`，生成的
`acid_wavetable_16x256.hex` SHA-256为
`5F1FCDE43F1C8BBD101BAC397EEEAEE4E18D4FFBC3B82410BD327748EF63BF3B`。

文件的`clm`元数据包含Xfer波表标记和2048点帧长。波表播放把每帧视作一个周期，
因此WAV头中的44.1 kHz只描述文件容器，不决定FPGA振荡器的输出音高。输出音高仍由
32位相位累加器和768 kHz内部采样率决定。

## 2. 第一阶段容量选择

第一版只导入16帧，每帧256点，每点16位：

```text
16 × 256 × 16 bit = 65536 bit = 8192 byte
```

从40个源帧中等间距选择以下帧：

```text
0, 3, 5, 8, 10, 13, 16, 18, 21, 23, 26, 29, 31, 34, 36, 39
```

这能覆盖完整波表运动，同时把每个物理引擎的单份逻辑ROM控制在64 Kibit。板级当前
有4个物理引擎，因此逻辑数据总量为256 Kibit。双读口能否由一个存储体实现取决于
Gowin综合器和目标BSRAM模式；若工具复制ROM，实际用量可能达到512 Kibit。

## 3. 帧内降采样方法

每个2048点源帧先做实数FFT，只保留256点目标帧能够表示的频率箱，再做逆FFT生成
256点周期。目标Nyquist频率箱被清零，避免这个特殊频率箱在实数序列中产生不连续
解释。最后四舍五入并饱和到16位有符号PCM。

这一步是在导入时完成的离线带限处理。它避免直接每隔8点抽样造成明显混叠，但单一
256点波表仍不能针对每个演奏音高分别限制谐波。现有768 kHz内部过采样和8倍FIR
降采样继续承担运行时的混叠抑制。

转换命令：

```powershell
python tools\convert_wavetable.py `
  C:\Users\ZhuanZ\Downloads\Acid.wav `
  src\acid_wavetable_16x256.hex
```

## 4. ROM地址与WT Position

ROM共有4096个字，地址定义为：

```text
address[11:8] = frame_index
address[7:0]  = phase_index
```

7位WT Position拆成4位帧号和3位小数：

```text
frame_index = wt_position[6:3]
fraction    = wt_position[2:0]
```

两个同步读口同时读取当前帧`A`和下一帧`B`的同一相位，输出为：

```text
sample = A + (B - A) × fraction / 8
```

第15帧没有后继帧，因此两个地址都固定到第15帧。WT Position 120～127会保持最后一
帧，不会回绕到第一帧。

## 5. TDM流水时序

同步ROM不能在给出地址的同一拍返回新数据。核心采用两级重叠调度：

```text
系统时钟拍       N        N+1      N+2      N+3
发出阶段       槽位0     槽位1     槽位2     槽位3
提交阶段         空      槽位0     槽位1     槽位2
```

发出阶段把槽位编号、相位、相位步进、包络、力度、Gate和波形选择一起锁存。下一拍
ROM数据到达时，提交阶段使用同一份槽位上下文更新相位和包络，并把采样加入部分和。
最后一个地址发出后再保留一拍排空流水线。

这样增加的是整批固定延迟，吞吐率仍为每拍一个槽位。RTL压力测试使用1引擎×32槽位，
仍能在50 MHz系统时钟和768 kHz内部采样时序下完成；实际顶层使用4引擎×8槽位。

## 6. 参数平滑与批次一致性

CC20先写入`wt_position_target`。顶层以96 kHz速率让`wt_position_current`每次最多
移动一级，然后每个TDM核心在一次768 kHz批次开始时锁存该值。由此得到两项性质：

1. 串口从0跳到127时不会在一个音频采样内突然跨越整个波表；
2. 同一批次的全部逻辑振荡器使用同一WT Position，不会因槽位先后顺序产生位置偏差。

## 7. MIDI控制方法

控制消息使用MIDI通道16：

```text
BF 15 7F    CC21=127，选择Acid波表
BF 14 00    CC20=0，移动到波表起点
BF 14 40    CC20=64，移动到波表中部
BF 14 7F    CC20=127，移动到波表终点
```

`tools/midi_uart_sender.py`的全局波形列表已增加“Acid波表”。选择后拖动WT Position
滑块即可试听帧轴变化。

## 9. 上板前仍需确认

本次遵循工程规则，没有自动运行Gowin综合和布局布线。用户下一次手动综合后应检查：

1. `acid_wavetable_rom.memory`是否映射为BSRAM；
2. 每个引擎实际消耗多少BSRAM，双读口是否造成ROM复制；
3. 50 MHz时钟的WNS/TNS是否通过，关键路径是否落在帧间插值或包络乘法；
4. `$readmemh`初始化文件是否被打包进位流，板上Acid模式是否输出非零且随WT Position变化。

如果插值到包络乘法的路径无法满足50 MHz，不应压缩现有调度状态机。优先增加一个
插值寄存级；由此增加的批次延迟仍可由当前4引擎×8槽位余量吸收。若以后每个槽位的
处理拍数继续增加，再提高`ENGINE_COUNT`并相应减小`SLOTS_PER_ENGINE`。
