## 2. 改了哪些路径

| 模块 | 原来的问题 | 本次边界 |
|---|---|---|
| Distortion | Drive 系数、增益乘法、整形、Tone、Mix 串在同拍 | 接收参数 → 系数 → Drive 乘积 → 整形 → Tone 乘积 → Tone 电平 → Mix 乘积 → 输出 |
| TDM / Warp | 大槽位选择器后紧接 Warp 操作数计算、乘法、地址输出 | 先寄存槽位快照，再分离 Warp 操作数、乘积和地址 |
| TDM / 波表增益 | BRAM 返回及帧间插值、包络乘法、混音累加串联 | 插值样本寄存 → 增益乘积寄存 → 舍入并累加 |
| TDM / ADSR | 阶段选择、相位加法、分段乘法在同拍 | 相位进度及分段操作数寄存 → 分段电平 → 状态写回 |
| Phaser | 最后一级全通结果直接进入 Mix 乘法 | 最后一级结果寄存，再执行 Mix |
| Chorus | 插值乘法后直接进入反馈和 Mix 乘法 | 插值后的湿声独立寄存 |
| Global Filter | Mix 乘法后立即求和及饱和 | 乘积和湿声寄存，再求和及饱和 |

Warp 的组合接口和流水接口共用 `wavetable_warp_prepare` / `wavetable_warp_finish`，没有复制两份不同的变形算法。新增模块仍在原 `wavetable_phase_warp.v` 中，工程文件不需要新增源文件。

### 已审查但保留的部分

- Detune / Vibrato 的乘法已移到槽位快照之后，结果加减与相位累加分开。
- Glide 控制器及调度器没有重写；实时 Glide / Vibrato 的原测试通过。Glide 覆盖下的步进系数生成仍需新报告确认。
- Reverb 保留现有分阶段同步存储结构，全通 RAM 读写模板不变；其梳状反馈阻尼、单次反馈乘法及写回仍可能成为后续关键路径，现有最坏路径列表不能给出其整改后裕量。
- 没有凭空给 DDR 或 `sys_clk_d` 加 false path。它们的约束与时钟资源问题不能由本次数据路径仿真证明已解决。

## 3. TDM 时序：没有等待全部槽位再计算

以接受 `start_tick` 的上升沿为第 0 拍。槽位 0：

| 上升沿 | 阶段 | 核心内对应名称 |
|---:|---|---|
| 0 | 锁存本批音色参数、启动调度 | `*_batch` |
| 1 | 读取槽位状态及原始地址 | `read_*` |
| 2 | Warp 操作数寄存；Detune / Vibrato 乘积 | `prepare_*` |
| 3 | Warp 乘积寄存 | `multiply_*` |
| 4 | 保存变形地址 | `request_*` |
| 5 | 同步 ROM 返回；槽位上下文同步推进 | `pipe_*` |
| 6 | 保存插值后的样本；保存 ADSR 进度/操作数 | `sample_*` |
| 7 | 保存波形×包络乘积及 ADSR 分段电平 | `commit_*` |
| 8 | 更新该槽位相位/包络，累加混音 | 状态数组、`mix_accumulator` |

槽位 1 比槽位 0 晚一拍，依次类推。仍为 **II=1**，32 槽位最后一次核心提交在第 **39** 拍；bank 归一化后的输出在第 **41** 拍。

在 50 MHz 下，41 拍为 0.82 µs。与 768 kHz 最短约 65 拍的间隔相比，bank 完成后还剩 24 拍。这个结论基于当前 32 槽位规模；增加槽位数必须重新检查预算。

## 4. 如何避免声音串槽或旧音符覆盖新音符

1. 各阶段携带对应的槽位号、相位、使能、门控及包络快照，音频值与其上下文同时推进。
2. 每一级推进时都检查同槽位 `task_update_valid`，把取消标记带到末端。
3. 最终写回的当拍再次检查更新冲突，更新操作拥有优先权。
4. 被取消的旧任务仍提交槽位序号，以便整批正确结束；但贡献零混音，不写相位/包络，也不会发出过期的 idle 通知。
5. `clear_phase` 会取消所有跨过该事件的旧上下文，避免稍后把旧相位写回来。复位清空所有流水有效标志。
6. 音符更新与在途旧任务相撞时，旧任务的本次贡献被丢弃，这是有意的保护；此场景不宣称与旧实现逐位相同，因为旧实现的最终提交拍存在旧任务混入输出的机会。

## 6. 新一轮布线应如何验收

本次集中处理已知长路径，不能保证一次消除原报告的全部违例：现有报告只展开有限条最坏路径，并未覆盖所有违反时序的端点。

新结果需要同时检查：

- 确认构建使用本次修改对应的提交，避免拿旧 `.fs` 或旧报告验收。
- `clk_sys` 的 Setup 最坏裕量至少为 0，TNS 为 0，违反端点为 0；同时检查 Hold、Recovery、Removal。
- 对比关键路径是否从 Distortion 串联运算、槽位选择→Warp、BRAM→包络→累加这些位置消失。
- DDR 时钟域单独检查；不能只看它的 Fmax 摘要便认为全部跨域和接口路径通过。
- 确认时钟走线、未约束路径、DSP/BSRAM 推断和资源变化合理。
- 上板检查持续按键、快速重触发、松键尾音、两个 OSC 独立开关、WT Position/Warp 扫动、效果反馈与旁路切换。

通过这些检查后，才能确认物理实现也保持正确发声并完成 50 MHz 时序收敛。
