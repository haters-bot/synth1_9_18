# 高云 FPGA 中型项目 AI 协作规范（初版）

> **用途**：本文件是给 AI 助手、开发者和评审者共同使用的工作约束。它不是器件手册的替代品；具体端口、电气参数、资源数量、IP 参数和工具行为必须以当前器件型号、当前 Gowin 软件版本及项目中保存的官方手册为准。

## 1. 项目基本原则

1. **先确认事实，再写代码**：未确认的器件型号、封装、速度等级、时钟频率、IO 电平、复位极性、吞吐率和延迟不得凭经验补全。
2. **以可综合、可仿真、可约束、可复现为完成标准**：仅能通过语法检查的 RTL 不视为完成。
3. **小步提交、单变量验证**：一次只改变一个关键变量；每个阶段保留可回退的中间结果和验证记录。
4. **优先使用 FPGA 专用资源**：时钟使用全局/区域时钟资源，乘加使用 DSP，深度缓存使用 BSRAM/SSRAM，避免用普通逻辑替代而造成时序或资源浪费。
5. **所有结论给出证据**：结论应能回溯到仿真波形、综合报告、布局布线报告、时序报告、板测日志或官方手册章节。
6. **不把警告当作噪声**：未解释的时序、CDC、锁相环、IO、电源、未连接端口和推断失败警告必须登记并关闭。
7. **确保项目负责人完全了解当前系统架构与进度**：系统结构设计，各模块顺序与时序逻辑要及时同步给负责人，避免系统黑箱化。
## 2. AI 的工作边界

### 2.1 AI 可以直接完成

- 梳理需求、接口和时序假设，建立模块边界和数据流。
- 编写/修改 Verilog/SystemVerilog、仿真 testbench、仿真脚本、约束文件和寄存器文档。
- 根据官方手册生成 Gowin IP 配置清单、封装模块和集成检查表。
- 分析综合、时序、CDC、功耗和资源报告，提出可验证的改进方案。
- 生成测试向量、断言、覆盖率计划、板级调试步骤和交付清单。

### 2.2 AI 不得擅自决定

- 不得自行更换 FPGA 型号、封装、速度等级、IO 标准、电压或时钟源。
- 不得根据“常见器件”猜测引脚、PLL 参数、BRAM 深度、DSP 结构或 IP 端口时序。
- 不得删除约束、关闭时序检查、屏蔽 CDC/DRC 警告来“让报告通过”。
- 不得在未说明影响的情况下改变接口协议、寄存器地址、数据位宽、舍入方式或复位行为。
- 不得把未验证的算法等价、时序收敛或硬件现象描述为已确认事实。
- 不得私自例化IP核，需要ip核时根据我给你的官方IP核文档给出具体配置选项，然后指导我配置，有缺失的官方文档就叫我补充。

## 3. 开始任务时必须收集的信息

如果信息缺失，先建立“待确认项”，再使用明确假设推进；不要默默猜测。

### 3.1 器件与工具

- FPGA 完整型号（例如 GW5AT 系列具体料号）、封装、速度等级、温度等级。
- Gowin EDA 版本、综合器/仿真器、操作系统和脚本入口。
- 板卡原理图、引脚表、时钟源、复位源、电源时序、配置方式和调试接口。
- 目标频率、时钟域数量、资源预算（LUT/FF/BSRAM/DSP/PLL/IO）和功耗目标。

### 3.2 功能与接口

- 输入/输出接口协议、数据位宽、符号位、定点小数位、端序和有效信号定义。
- 吞吐率、允许延迟、缓存深度、背压行为、丢包/溢出/欠载策略。
- 复位顺序、异常恢复、上电默认状态和寄存器可见行为。
- 验收用例、边界条件、误差指标和必须观测的内部信号。

## 4. 推荐目录与命名

建议项目结构如下，可按现有仓库调整但要保持职责清晰：

```text
project/
├─ rtl/                 # 可综合 RTL
│  ├─ common/           # 复位、CDC、计数器、寄存器等通用模块
│  ├─ core/             # 算法和业务逻辑
│  └─ top/              # 顶层与板级封装
├─ ip/                  # Gowin IP 工程、配置快照和生成文件
├─ sim/                 # testbench、脚本、参考模型、波形配置
├─ constraints/         # .cst/.sdc 及约束说明
├─ board/               # 原理图导出、引脚表、上板配置
├─ scripts/             # 综合、仿真、报告解析和一键构建脚本
├─ docs/                # 接口、寄存器、时序、验证和变更记录
└─ reports/             # 不纳入源码的构建报告与板测日志
```

命名建议：模块/文件使用 `snake_case`；时钟使用 `clk_<domain>`；复位使用 `rst_n_<domain>` 或 `rst_<domain>`；跨域信号显式包含源/目的域；有效信号统一使用 `*_valid`，握手信号使用 `*_ready`。

## 5. 需求分析与架构设计流程

每个功能需求先输出以下内容，再进入 RTL：

1. **输入/输出表**：名称、方向、位宽、时钟域、协议、默认值。
2. **时序预算**：时钟频率、单周期/多周期、最大延迟、吞吐率和背压。
3. **状态与数据流**：状态机、FIFO/缓存、算子流水级、异常路径。
4. **资源估算**：LUT/FF/BSRAM/DSP/PLL/IO 的粗略预算及依据。
5. **风险清单**：CDC、复位释放、定点溢出、DDR 校准、IP 黑盒、引脚冲突、时序瓶颈。
6. **验收标准**：可测量的功能、性能、资源、时序和板级指标。

架构评审至少回答：

- 数据在哪些时钟域之间移动？每条跨域路径采用何种 CDC 结构？
- 哪些运算必须映射到 DSP，哪些存储必须映射到 BSRAM/SSRAM？
- 最长组合路径在哪里？流水线边界和 valid 延迟是否一致？
- 复位时各模块的初值、释放顺序和异常恢复是否定义？
- IP 的配置、生成版本、时钟/复位要求和仿真模型是否可复现？

## 6. RTL 编码规则

### 6.1 通用规则

- 使用 `always_ff`/`always_comb`（若工具链支持并已统一）；否则严格区分时序块和组合块。
- 时序逻辑使用非阻塞赋值，组合逻辑使用阻塞赋值；避免同一信号多处驱动。
- 所有组合块覆盖完整赋值，避免锁存器；状态机包含默认分支和非法状态恢复。
- 参数化位宽、深度和延迟；禁止散落的魔数，统一定义常量和寄存器字段。
- 有符号运算显式声明 `$signed`/`$unsigned`，明确扩展位、截位、舍入和饱和策略。
- 计数器、指针和长度比较必须考虑回绕、边界值和非 2 的幂深度。
- 关键接口使用 SystemVerilog assertion 或等价检查表达协议不变量。

### 6.2 复位与时钟

- 每个时钟域定义唯一的复位策略；异步输入复位建议“异步置位、同步释放”。
- 不使用普通逻辑门直接门控时钟；需要停钟时优先使用器件支持的时钟使能/专用资源。
- PLL 输出必须经过锁定检测和复位释放控制；锁定丢失要定义系统行为。
- 不把数据使能误当作时钟；不得在 RTL 中生成不可约束的派生时钟。

### 6.3 CDC

- 单 bit 控制信号使用双触发器同步；脉冲使用脉冲展宽、握手或 toggle 方案。
- 多 bit 数据使用异步 FIFO、握手锁存或 Gray 指针结构，禁止逐 bit 独立同步后直接拼接。
- 异步 FIFO 必须验证满/空、近满/近空、复位交叉和指针回绕。
- 每条 CDC 路径在设计文档中记录源域、目的域、结构、延迟和复位要求。

### 6.4 FIFO、RAM 与 DSP

- FIFO 明确 show-ahead/standard 模式、读写冲突行为、almost-full/empty 阈值。
- RAM 明确单口/简单双口/真双口、读延迟、初始化文件和读写同址行为。
- 优先实例化或正确推断 Gowin BSRAM/SSRAM、DSP；综合后检查是否真正映射到目标资源。
- DSP/滤波/FFT 等定点链路记录每级位宽、缩放、舍入、饱和和误差预算。

## 7. Gowin IP 使用规范

1. IP 配置必须保存：IP 名称、版本、器件、参数截图或导出配置、生成时间和依赖文件。
2. 对 FIFO、DDR3、FFT、DDS、CORDIC、FIR、IIR 等 IP，先阅读对应 `IPUG*.pdf` 的时钟、复位、端口时序和限制章节。
3. 生成 IP 后编写本地 wrapper，隔离厂商端口命名和工程路径，禁止业务逻辑直接散落连接 IP 黑盒。
4. 仿真必须使用官方仿真模型或已验证替代模型；综合与仿真参数必须一致。
5. IP 升级前保留旧版本工程和回归结果，记录接口、延迟、资源和时序变化。

## 8. 约束与时序收敛

### 8.1 约束最低要求

- 所有外部时钟使用 `create_clock`，写明周期、波形和来源。
- 为输入/输出建立时序约束；对真实异步时钟、互斥时钟和不参与时序的路径给出有依据的例外。
- 引脚约束包含位置、IOSTANDARD、驱动/ slew（若适用）、上下拉和差分属性。
- 约束文件纳入版本控制，并在报告中确认“约束已加载且无未约束时钟/端口”。

### 8.2 收敛顺序

1. 先修正时钟定义、CDC 和明显的组合环路；
2. 再处理最大负裕量路径，定位逻辑深度、扇出、布局和跨区域问题；
3. 根据证据选择流水线、资源映射、扇出复制、布局约束或频率调整；
4. 每次修改后重新综合、布局布线和时序分析，记录 WNS/TNS、关键路径和资源变化；
5. 禁止仅通过放宽约束或添加无依据的 false path 伪造收敛。

## 9. 验证策略

### 9.1 分层验证

- **单元级**：组合算子、FIFO、CDC、寄存器、状态机和定点函数。
- **子系统级**：数据通路、控制通路、缓存和 IP wrapper 的联调。
- **顶层级**：时钟/复位、接口协议、异常恢复和完整数据流。
- **门级/时序级（必要时）**：对关键路径、复位、DDR、PLL 和边界接口进行检查。
- **板级**：配置成功、时钟锁定、复位释放、链路训练、吞吐率、长时间稳定性。

### 9.2 测试要求
- 改动代码后不要擅自操作eda进行综合布线以验证代码，只运行verilog语法检查就行。
- 正常、边界、错误、复位中断、突发流量、反压和时钟比变化都要有用例。
- 参考模型优先使用独立实现，避免 testbench 与 DUT 复制同一错误。
- 记录随机种子、工具版本、参数快照和波形位置，使失败可复现。
- 验证报告至少包含：通过用例数、覆盖率/未覆盖项、已知限制和剩余风险。

## 10. 调试与故障定位

按“最早可观测失败点”排查：

1. 配置文件/器件识别是否正确；
2. 电源、复位、外部时钟和 PLL lock 是否正常；
3. 输入接口是否满足电平、时序和协议；
4. CDC/FIFO 是否出现丢脉冲、重复、满空误判；
5. 数据路径是否存在位宽、符号、缩放或延迟错位；
6. 输出接口、缓存和软件读取顺序是否匹配。

调试信号应有明确选择依据，优先观测：复位、PLL lock、valid/ready、FIFO level、状态机状态、错误计数器、关键数据片段和时间戳。增加 ILA/片上逻辑分析资源后必须复查时序和资源影响。

## 11. 交付前检查清单

### 11.1 源码与工程

- [ ] 顶层、文件列表、器件、封装、速度等级和工具版本已固定。
- [ ] IP 配置、生成脚本/文件和版本信息完整。
- [ ] RTL 无未解释的综合警告、锁存器、三态误用、未连接端口和多驱动。

### 11.2 约束与报告

- [ ] 时钟、IO、CDC、异步路径和例外约束有依据且已加载。
- [ ] 无未约束时钟/端口；WNS/TNS、时钟偏斜和关键路径满足目标。
- [ ] LUT/FF/BSRAM/DSP/PLL/IO 使用率留有余量，功耗在目标内。

### 11.3 验证与板测

- [ ] 回归测试通过，边界和错误用例有记录。
- [ ] 配置、复位、接口、吞吐率、延迟、长稳和异常恢复已在目标板验证。
- [ ] 生成物、校验和、烧录方式、版本号和回滚方案已归档。

## 12. AI 输出格式建议

AI 每次提交设计方案或代码时，尽量按以下结构回答：

1. **结论/变更摘要**：做了什么，未做什么。
2. **依据与假设**：引用的器件/IP 文档、已确认事实、待确认项。
3. **实现内容**：文件、模块、接口、参数和关键时序。
4. **验证方法**：仿真用例、静态检查、综合/时序检查和板测步骤。
5. **风险与后续动作**：已知限制、可能失败点、需要用户确认的选择。

涉及数值时统一标注单位和格式，例如 `200 MHz`、`5 ns`、`Q1.15`、`WNS = +0.32 ns`。禁止只给“应该可以”“时序没问题”这类无证据结论。
