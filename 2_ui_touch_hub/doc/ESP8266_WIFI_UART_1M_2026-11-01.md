# ESP-01S Wi-Fi 串口桥接 1 Mbps（2026-11-01）

本轮目标限定为：ESP-01S 只做 Wi-Fi TCP 与 UI FPGA UART 的双向字节桥，
不解析 MIDI、不生成网页、不改变音频板协议。现有帧头、CRC、ACK、录音身份及
手机断点续传仍由 UI FPGA 和 App 负责。

## 已完成

- UI FPGA `performance_phone_transport` 增加第四路 `1000000` baud，HELLO 的
  CRC 正确者锁定速率；旧的 9600/115200/230400 保留。
- UI FPGA TX/RX 使用 50 MHz 时钟下 50 个时钟/bit（精确 1 Mbps）；状态扩展
  的速率码为 `3`，App 解析为 `1000000`。
- 安卓 App 增加蓝牙／Wi-Fi TCP选择。Wi-Fi路径使用手机当前 Wi-Fi 网络的
  SocketFactory，避免手机同时开着蜂窝网络时把局域网连接走错接口；TCP启用
  `TCP_NODELAY`。蓝牙路径保持不变。
- ESP-01S桥接固件源代码位于 `esp8266_bridge/`：AP `FPGA-ESP01S`、密码
  `PianoLink1M`、地址 `192.168.4.1`、TCP 333、UART0 1 Mbps 8N1，单客户端、
  8 KiB突发缓冲，拥塞溢出主动断开以便 App 从已提交PCM块续传。

## 不能混淆的边界

目录中的安信可 2017 AT 固件是通用联网固件，默认 UART 115200；它没有本项目
的 AP/TCP参数和业务协议。要使用本方案，ESP必须烧录 `esp8266_bridge`生成的
桥接固件，而不是直接烧录原厂 AT 固件。当前机器未安装 PlatformIO/ESP8266
Arduino构建环境，所以桥接固件**尚未编译或烧录**；不得把源代码当成已验证固件。

ESP-01S UART0 与 UI 接线：TX→F16（UI RX），RX→F14（UI TX），GND共地，3V3
使用有足够瞬态电流的稳压电源；EN/RST/IO0/IO2按正常启动上拉。烧录时由下载器
令 IO0 在复位时为低，完成后恢复高电平。烧录和换线前断开 HC-07。

## 验证结果与下一步

四档 UART 仿真、50 MHz 1 Mbps 双向帧、录音身份/续传、旧功能回归及 App完整回归
均通过；最终 APK 0.3.0 已编译签名，但没有实机、ESP物理链路或长时间吞吐结果。
必须在烧录后测量 HELLO/ACK、持续 B/s、CRC错误、断连、ESP复位和8 KiB拥塞行为，
再决定是否把速率提高到2 Mbps。1 Mbps理论值不等于无线有效吞吐。
