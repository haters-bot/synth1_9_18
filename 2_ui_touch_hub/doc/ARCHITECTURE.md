# UI Touch Hub (Teammate 2) 系统架构与三方解耦协议手册

> **竞赛题目**：全国大学生嵌入式芯片与系统设计竞赛 —— 高云赛道第二题 (基于 FPGA 的实时多音色合成电子乐器引擎)  
> **核心硬件平台**：Sipeed Tang Mega 138K Dock (`GW5AST-LV138PG484AC1/I0`，晨熙五代 138K LUT)  
> **本子系统定位**：`2_ui_touch_hub` —— 纯硬件 HDMI 矢量图形渲染、多维触控响应、实体旋钮 SPI 汇聚、参数合并中枢与 UART MIDI 演奏协议发送引擎。

### 1. 模块职责边界
- **队友 1 (面板硬件)**：负责电位器 ADC 采样，通过简单标准 SPI 从机协议向 UI Hub 汇报物理旋钮位置；
- **队友 2 (UI Touch Hub，本项目)**：
  1. 采用**纯硬件数学矢量光栅化流水线**输出 1280x720 高清 HDMI 信号，彻底消除 BRAM 位图量化噪声、蓝绿噪点和第 4 排控件被裁切的问题；
  2. 接收便携屏 USB/UART 触控坐标，完成虚拟琴键、旋钮角度、包络控制点碰撞检测与交互；
  3. 接收队友 1 的 SPI 旋钮数据并进行数字滤波与滞后消抖 (Hysteresis)；
  4. 维护全系统主控参数寄存器，实现触控与实体旋钮无缝接管合并；
  5. 将所有琴键演奏事件与参数调制严格编码为标准 MIDI 字节流 (Ch1 音符，Ch16 CC 参数)，通过单线 UART 发送给队友 3。
- **队友 3 (音频引擎 `synth1_9_18`)**：专注于声音合成核，只接收 UART MIDI 输入，无需关心任何显示或触控逻辑。

## 二、 纯硬件矢量光栅化流水线 (Procedural Vector UI)

### 1. 彻底解决历史遗留缺陷
- **历史缺陷 1：蓝绿杂色噪点与条带**：原方案试图在 FPGA 有限的 BSRAM (6.1Mb) 中塞入 900x600 压缩调色板位图，导致高位量化失真与内存带宽竞争。
  - **解决方案**：**彻底摒弃位图 ROM**，采用 100% 纯数学几何解析生成 (Procedural Vector Graphics)。所有面板背板、边框高光、凹陷质感、网格刻度均为实时公式计算，**BSRAM 占用降为 0**，画面边缘绝对锐利纯净。
- **历史缺陷 2：第 4 排控件与琴键被裁切**：原方案误用 1024x600 非标时序渲染 900x600 画布，底部留白仅 70 像素，导致钢琴键变形或旋钮裁切。
  - **解决方案**：切换到行业标准 **720p (1280x720@50.5Hz/60Hz)** 时序。1280x720 为原生 16:9 比例，所有便携显示器均可点对点无缝满屏显示，纵向空间充裕展开，所有 4 排旋钮与 24 个全尺寸钢琴键完美舒展。

## 三、 时钟树与流水线规划

- **输入时钟**：板载 50MHz 有源晶振 (`V22`)；
- **锁相环 PLL**：
  - `clk_pixel` = 62.5MHz (720p 像素时钟)；
  - `clk_5x_bit` = 312.5MHz (OSER10 DDR 差分串行位时钟)；
- **流水线分级**：
  - Stage 0: 像素坐标 `(pixel_x, pixel_y)` 锁存与参数寄存器取样；
  - Stage 1: 几何边界判决 (Bounding Box Test) 与相对坐标偏移提取；
  - Stage 2: 曲线函数计算 (波表正弦/锯齿查表、ADSR 定点乘法折线、Filter 拐点衰减曲线)；
  - Stage 3: 旋钮欧氏距离与指针对角线投影判决、琴键碰撞计算；
  - Stage 4: 优先图层混合器 (Background -> Panel -> Grid -> Waveform Fill -> Waveform Stroke -> Knobs -> Feedback)；
  - Stage 5: DVI 编码器 (8b/10b TMDS 编码与极性对齐)；
  - Stage 6: OSER10 10:1 硬件差分串行输出驱动。
