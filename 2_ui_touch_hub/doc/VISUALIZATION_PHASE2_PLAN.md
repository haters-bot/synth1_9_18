# 第二期：六种演奏可视化的可行性与接口建议

> 2026-10-19更新：用户已选择**一屏六小窗，3列×2行**，不采用下方早期六个全屏视图方案。R17框架/菜单/系统页进度与验收以 `R17_NAVIGATION_SIX_WINDOWS_2026-10-19.md` 为准；以下数据链路、分析器和资源估算仍是规划，尚未接入。

下文为R16阶段的可行性调研，保留作接口依据；其中“六页”和旧时序状态是历史设想。R17已实现同一可视化页的六个窗口、导航与系统页，保留唯一HDMI时序发生器和50MHz像素时钟。分析数据仍未接入，以下“可行”是架构评估，尚未完成FFT综合或真实音频实屏验证。

## 六个窗口的数据与功能建议

| 页 | 展示 | 作用 | 最低数据 | 建议刷新 |
|---|---|---|---|---|
| 1 音符 / 演奏轨迹 | 当前和弦、按键高亮、力度条、音符瀑布 | 直接解释演奏输入，排查键盘事件丢失 | Note On/Off、音高、力度、时间戳、通道；可选实际基频 | 30–60 Hz |
| 2 立体声示波器 | L/R 波形、触发、电平和削波指示 | 看波形、包络、爆音和电平余量 | 同步 PCM L/R 与采样率 | 30 Hz |
| 3 李萨如 / 立体声相位 | X=L、Y=R，轨迹余辉、相关系数 | 看立体声宽度与反相关；实际为单声道时应显示对角线 | 同一采样时刻的 L/R PCM | 30 Hz |
| 4 频谱 | 对数频率轴、64/128 柱、峰值保持 | 看基音、谐波、滤波器和效果变化 | PCM 或音频核算好的频段能量 | 20–30 Hz |
| 5 瀑布频谱 | 时间×频率×颜色、可暂停 | 展示音色随时间的变化，适合演示调制 | 与频谱共用 FFT 数据 | 15–30 行/秒 |
| 6 电平 / 调制仪表 | 峰值、RMS、削波计数、ENV/LFO轨迹和目标值 | 三人联调、检查调制与声音的对应关系 | 电平统计、活动声部、带时间戳的参数与调制值 | 20–30 Hz |

音符事件可说明“弹了哪个键”，不能作为实际音高检测结果；想测输出实际音高，另加自相关/YIN等估计器，多音时不能用单一基频冒充所有音符。李萨如单声道对角线是真实结果，不能为美观伪造左右差异。

## 数据链路是先决条件

已核对团队 GitHub `haters-bot/synth1_9_18` main `838b134764a6eaed6c092ba8ebad17084f3374bd` 中 `docs/midi_control_protocol.md`、`docs/lfo_curve_control.md`：音频为96 kHz，当前I2S将同一份单声道复制到左右。现有UI接收的是触控/旋钮控制，并没有音频PCM输入。

- 31250 bit/s、8N1 的 MIDI UART 净吞吐上限3125字节/秒。96 kHz、16 bit、双声道 PCM 是384000字节/秒，约为该上限123倍，不能塞进现有MIDI口。
- 单声道/双声道切片可由音频核降采样、抽取或统计，再通过独立高速链路发送。优先研究从现有I2S并行监听，或新建带帧同步的SPI/源同步接口；必须核实两板引脚、电压、主从时钟和接地。
- 若传96 kHz、24 bit双声道，纯载荷4.608 Mbit/s；10 MHz SPI理论可容纳但要扣帧头、校验、暂停和仲裁，建议评估20–25 MHz并做真实时序/丢包测量，不能仅凭理论带宽验收。
- 若只传64频段×16 bit×30帧/秒，也需3840字节/秒，尚未算帧头便超过MIDI口。32频段×16 bit×20帧/秒为1280字节/秒，仍会挤占演奏消息；独立遥测链路更稳妥。

## 资源与计算初步估算

- 使用已有1280×720输出，暂不提升PLL/分辨率。R16已验收构建的50MHz像素域时序闭合；R17和后续每个新增分析器的候选仍须单独完成全时序审计，不能继承旧版通过结论。
- 1024点FFT：96 kHz时频率间隔93.75 Hz，对低音区粗；抽取到24 kHz后约23.44 Hz，需先抗混叠低通，并接受最高12 kHz分析范围。2048/4096点可进一步细化低频，但增加存储和计算延迟。
- 以1024点、16 bit I/Q两缓冲估算8 KiB；双声道1024采样双缓冲另约8 KiB；256×64、8 bit瀑布历史约16 KiB。这只是数据存储量，不含FFT工作区、字形、接口FIFO和实现开销，必须以综合报告核实。
- 720p RGB565双帧缓冲需要1280×720×2×2=3686400字节，约3.52 MiB；不能假设片内BSRAM可直接容纳。优先按当前光栅逐像素绘制，只保存波形采样、频谱柱和低分辨率瀑布索引；必要时再引入DDR。
- FFT在音频/分析时钟域按块运算，像素域只读已完成结果。可复用一个分析器服务第4、5页，避免每页各建FFT。

## 隔离当前工作界面

R17已采用 `view`：0为合成器控制台，1为六窗口可视化，2为系统页，3为菜单。唯一HDMI时序发生器不变，导航在VSYNC上升沿提交；页面切换不重置USB与参数。合成器和导航触摸已隔离，返回后曲线、FX、LFO绑定保持。未来数据采集与分析应在后台继续，不能随页面隐藏而丢弃Note Off或暂停音频。

分析域与像素域采用双缓冲加序号，在垂直消隐时交换可读缓冲；跨时钟消息用异步FIFO/握手，禁止直接跨域读取变化中的数组。规定采样率、位宽、左右同步、时间戳、丢帧计数、饱和方式和复位行为。数据失联时冻结并显示数据状态，不能继续循环演示数据假装是实时声音。

## 推荐实施顺序与验收

1. 确认音符事件流与PCM取样位置，补齐链路引脚/电气/时钟约定；收敛当前像素时序。
2. 先做音符页和示波器，验收已知音符、已知幅值正弦、静音、削波、掉线恢复。
3. 加李萨如，用L=R、L=-R、90°相移三组信号核验对角线、反对角线和圆/椭圆。
4. 加FFT与瀑布：用整周期和非整周期正弦核验峰位、窗函数、幅度标定；测试混频、低音、满载和切页。
5. 加统计仪表，联合测量输入到显示延迟、丢帧率、时序与资源。测试页面切换期间Note Off不丢失、声音不断、控制台参数不跳变。

目前六窗口页面框架已实现；真实演奏可视化的数据源和带宽仍未落地，不能承诺接上现有MIDI线即可实现所有六种分析。建议接入顺序为Note事件与电平统计 → PCM示波器/丽萨如 → 共享FFT的频谱/瀑布，优先复用队友已有输出，避免在协议和物理线未确认前编造输入。
