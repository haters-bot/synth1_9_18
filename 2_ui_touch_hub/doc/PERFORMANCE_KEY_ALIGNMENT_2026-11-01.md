# PERFORM 起音校准、实体琴键对应与提示

## 结论与操作

用户确认：把键盘最左键从 `0x29` 切到 `0x35` 后，没有在 UI 重新校准。因此本次错位的直接原因是旧校准仍然有效，不是已经发现并修复了 `note - base` 索引运算错误。

换档后按以下流程操作：

1. 在 PERFORM 页点 `CALIBRATE`，等待 `LEFTKEY`。
2. 按实体键盘最左键，确认 UI 起音及下方范围更新。
3. 让 App 读取新校准状态，重新适配并传输歌曲；旧音域的已上传曲谱会失效。

| 最左键（十六进制） | 最右键（十六进制） | 屏幕对应 |
|---|---|---|
| 0x29 | 0x48 | 32键，逻辑索引0～31 |
| 0x35 | 0x54 | 32键，逻辑索引0～31 |
| 0x41 | 0x60 | 32键，逻辑索引0～31 |
| 0x4D | 0x6C | 32键，逻辑索引0～31 |

最左键为0x35并重新校准后，0x35使最左虚拟键变黄，0x54使最右虚拟键变黄，松键恢复白/黑键背景。

## 原因复现与边界

旧起音0x29下收到0x35，差值为12，所以显示第13键；收到0x54时已超出0x29～0x48，不会显示。回归已通过真实31250 baud键盘UART复现这两个现象。

单个MIDI Note只表达绝对音高，不能区分“旧音域的第13键”与“升八度后最左键”。不能靠第一个音符、取模或自动折八度猜起音，否则正常弹奏也会改变实体键/曲谱/灯带的对应关系。保留显式校准，不改变MIDI或音频板协议。

越界提示也无法识别所有换档情况：只在新旧音域重叠区内弹奏时，没有足够信息发现换档。**无论提示是否出现，换档都要重新校准。**
