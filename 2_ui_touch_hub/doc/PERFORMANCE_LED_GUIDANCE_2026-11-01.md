# 演奏灯带指引与音高配色修复

## 范围和部署状态

用户要求：空闲时按键反馈保留；开始演奏后，灯带应在曲谱要求按键的时刻提示，而不是等实际按下才亮。允许按音高变色。只做源码和仿真，等用户明确要求统一构建后才启动 Gowin。

本轮只修改 UI 板的 `rtl/ui_vector_engine/ui_top_renderer.v`，新增 `sim/tb_performance_led_guidance.v` 和本文；不修改音频板、音频协议、手机 App、引脚、现有页面或播放调度器。上一轮 SD 波表本地预览提交 `30aba7058bf3c1fbd0f862087930aee4a0765379` 完整保留。

**没有运行 Gowin 综合布线，没有烧录 SRAM/Flash，没有推送或删除文件。实板仍是此前部署版本 UserCode 0x171D；本轮灯带及此前本地波表预览都尚未上板。**

## 根因

1. 跟弹调度器故意等待正确的实体 Note On，之后才输出该曲谱事件。因此 `performance_guide_keys` 在等待第一次正确按键时仍为零，单纯依赖此位图无法提前提示。
2. `performance_active_keys` 本身包含曲谱、触摸、远程和实体按键，旧灯带逻辑始终使用它。手按反馈会混入演奏提示。
3. 旧 RGB 逻辑先判断 active，后判断 guide；曲谱位又已包含在 active 中，所以 guide 的单独颜色也常被覆盖。原来本身输出 RGB，并不是只能显示白色，只是主要使用固定暖白色。

## 最小修改

- 新增到时目标位图：当调度器当前记录为有效 Note On、在校准音域内，且 `next_time_ms <= song_time_ms` 时，将目标键加入 LED 指引。**不消费事件、不伪造按键、不改变跟弹前进条件**。
- 演奏运行期间，灯带只使用曲谱已生效音符与到时待按目标；忽略手按、触摸和远程按键产生的附加亮灯。试听、跟弹、演奏三种模式均如此。
- 跟弹模式目标灯在正确按键前就亮；按错保持等待。已经生效的曲谱音符按其 Note Off 时刻熄灭，和弦可同时亮多颗灯。
- 未播放时保留原按键反馈。暂停保留当前曲谱提示，停止后恢复空闲反馈；退出演奏页、校准失效时输出熄灭帧。
- RGB 按19个白键的物理顺序从低到高渐变：红 → 橙 → 黄 → 绿 → 青 → 蓝 → 紫。安全的四个校准八度共用同一物理键/颜色关系，不随移高八度更换灯号。
- 每个颜色通道不超过 `0x20`，延续低亮度设置。仅19颗白键灯参与，黑键继续靠屏幕指引，剩余5颗始终熄灭。
- 保留整帧冻结位图和 WS2812 GRB 发送器。颜色/按键变化在下一完整帧更新，避免一帧撕裂。50MHz下每帧24颗的发送与复位约1.015ms；这不是零延迟光学实测。
